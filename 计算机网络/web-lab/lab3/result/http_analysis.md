# 实验3：HTTP 抓包报文逐条分析（基于 `result/lab3.pcapng`）

## 捕获概况
- 报文来源：本机浏览器访问 `http://localhost:8000/index.html`，服务器为 `python -m http.server 8000`（HTTP 明文）。
- 抓包文件：`result/lab3.pcapng`，链路类型为 Loopback（pcapng linktype 0，4 字节协议标识，无真实 MAC）。
- IP 层全部为 IPv6 本地地址 `::1`<->`::1`，传输层为 TCP，应用层为 HTTP/1.1 请求与 Python SimpleHTTP 生成的 HTTP/1.0 响应。
- 浏览器为 Edge/Chromium，自动建立两条 TCP 连接：一条获取 `index.html`，另一条获取 `favicon.ico`。

## 报文逐条说明（长段中文）

### 连接 A（客户端端口 64883 → 服务端 8000，请求 `index.html`）
1. **报文 idx0 SYN**：链路层是 Loopback 伪头，无源/目的 MAC；网络层为 IPv6，源 `::1`、目的 `::1`，载荷指向 TCP；传输层 TCP 源端口 64883 → 8000，SYN=1、Seq=1792845184、窗口 65535，无负载；应用层无内容，开启三次握手。
2. **报文 idx1 SYN/ACK**：仍是 Loopback+IPv6；服务器 8000 → 客户端 64883，SYN/ACK 置位，Seq=1737695183，Ack=1792845185（对客户端 SYN+1 确认），窗口 65535；无应用数据，回应握手。
3. **报文 idx2 ACK**：客户端 64883 → 8000，ACK 置位，Seq=1792845185，Ack=1737695184，窗口 255；完成三次握手，连接建立，应用层仍为空。
4. **报文 idx3 HTTP GET**：客户端首个带数据报文，IPv6 载 TCP PSH/ACK，Seq=1792845185，Ack=1737695184，负载 772 字节；应用层为明文 `GET /index.html HTTP/1.1`，Host 为 `localhost:8000`，包含 UA、Accept、Accept-Language、If-Modified-Since 等请求头，表明浏览器要拉取主页。
5. **报文 idx4 ACK**：服务器对上述 GET 的纯确认，Seq=1737695184，Ack=1792845957（对 772 字节请求的累积确认），窗口 252，无应用数据。
6. **报文 idx8 HTTP/1.0 200 OK 首部**：服务器发回首个响应报文，PSH/ACK，Seq=1737695184，Ack=1792845957，负载 187 字节；应用层是 `HTTP/1.0 200 OK` 响应头，Server=SimpleHTTP/0.6 Python/3.12.7，Content-Type=text/html，Content-Length=4012，Last-Modified=Wed, 31 Dec 2025 09:42:48 GMT。
7. **报文 idx9 ACK**：客户端对响应头的确认，Seq=1792845957，Ack=1737695371，无数据；通知服务器已收到 187 字节。
8. **报文 idx10 HTML 数据段 1**：服务器继续下发主体，ACK 置位（无 PSH），Seq=1737695371，Ack=1792845957，负载 1440 字节；内容为 HTML 开头、CSS 等，属于 `index.html` 的正文第一段。
9. **报文 idx11 HTML 数据段 2**：同一连接继续传输，Seq=1737696811，Ack=1792845957，负载 1440 字节；仍是页面主体的中间部分（样式、排版）。
10. **报文 idx12 HTML 数据段 3（收尾）**：服务器最后一段数据，PSH/ACK，Seq=1737698251，Ack=1792845957，负载 1132 字节；包含页面中个人信息与 6 张图片 `<img>` 标签区域以及页脚提示，标志正文发送完毕。
11. **报文 idx13 ACK**：客户端确认全部 HTML 数据，Seq=1792845957，Ack=1737699383，无数据；服务器窗口继续开放。
12. **报文 idx14 FIN/ACK（客户端）**：浏览器主动关闭该 TCP 连接，Seq=1792845957，Ack=1737699383，FIN=1、ACK=1，无负载；表示主页内容收取完成。
13. **报文 idx15 ACK（服务器对 FIN）**：服务器确认客户端的 FIN，Seq=1737699383，Ack=1792845958，无数据；准备半关闭。
14. **报文 idx16 FIN/ACK（服务器）**：服务器发送自己的 FIN，Seq=1737699383，Ack=1792845958，FIN=1、ACK=1，无负载；请求关闭方向。
15. **报文 idx17 最终 ACK**：客户端对服务器 FIN 的确认，Seq=1792845958，Ack=1737699384，无数据；连接 A 四次挥手结束。

### 连接 B（客户端端口 54319 → 服务端 8000，请求 `favicon.ico`）
16. **报文 idx5 SYN**：Loopback+IPv6，同样是新建 TCP 连接，客户端端口 54319，Seq=4172531794，窗口 65535，SYN=1，无应用负载。
17. **报文 idx6 SYN/ACK**：服务器 8000 → 54319，SYN/ACK，Seq=2706956766，Ack=4172531795，窗口 65535；握手第二步。
18. **报文 idx7 ACK**：客户端 ACK，Seq=4172531795，Ack=2706956767，窗口 255；握手完成，连接 B 建立。
19. **报文 idx18 HTTP GET /favicon.ico**：客户端发送 PSH/ACK，Seq=4172531795，Ack=2706956767，负载 648 字节；应用层请求行 `GET /favicon.ico HTTP/1.1`，Host=localhost:8000，Accept 为多种图片类型，Referer 指向 `/index.html`，说明浏览器自动取图标。
20. **报文 idx19 ACK**：服务器确认 GET 请求，Seq=2706956767，Ack=4172532443，无数据；表明收到了 648 字节。
21. **报文 idx20 HTTP 200 图标首部**：服务器 PSH/ACK，Seq=2706956767，Ack=4172532443，负载 189 字节；应用层为 `HTTP/1.0 200 OK` 响应头，Content-Type=image/x-icon，Content-Length=104，Last-Modified: Wed, 31 Dec 2025 09:43:01 GMT。
22. **报文 idx21 ACK**：客户端确认响应头，Seq=4172532443，Ack=2706956956，无数据；准备接收图标主体。
23. **报文 idx22 图标数据**：服务器发送 PSH/ACK，Seq=2706956956，Ack=4172532443，负载 104 字节；负载开头为 PNG/Ico 二进制魔数（`89 50 4E 47` 等），即 `favicon.ico` 的文件内容。
24. **报文 idx23 ACK**：客户端确认图标数据，Seq=4172532443，Ack=2706957060，无数据；所有有效载荷已收完。
25. **报文 idx24 FIN/ACK（客户端）**：浏览器主动关闭图标连接，Seq=4172532443，Ack=2706957060，FIN=1、ACK=1，无负载。
26. **报文 idx25 ACK（服务器对 FIN）**：服务器确认客户端 FIN，Seq=2706957060，Ack=4172532444，无数据。
27. **报文 idx26 FIN/ACK（服务器）**：服务器发送自己的 FIN，Seq=2706957060，Ack=4172532444，FIN=1、ACK=1，无负载。
28. **报文 idx27 最终 ACK**：客户端对服务器 FIN 的确认，Seq=4172532444，Ack=2706957061，无数据，连接 B 释放。

## 交互过程概括
- 浏览器首先发起连接 A 完成三次握手（idx0–2），发送 `GET /index.html` 请求（idx3），服务器分四段回送 HTTP/1.0 200 OK 及 4012 字节 HTML 正文（idx8、10、11、12），客户端确认后主动挥手关闭（idx14–17）。这一过程展示了 TCP 建立、可靠传输（多段 ACK 确认）、以及四次挥手的完整流程。
- 浏览器随后为站点图标开启独立的连接 B（idx5–7），发送 `GET /favicon.ico`（idx18），服务器回 200 OK 响应头与 104 字节图标数据（idx20、22），客户端同样在数据收齐后主动关闭（idx24–27）。这体现了浏览器并行复用多个 TCP 连接获取资源的行为。
- 全部报文在 Wireshark 使用显示过滤器 `http` 即可呈现仅 HTTP 相关的 TCP 报文；链路层为本机 Loopback，网络层为 IPv6 本地回环 `::1`，传输层为 TCP 可靠传输，应用层为明文 HTTP，无 TLS 加密，便于观察请求行、响应头与正文内容。

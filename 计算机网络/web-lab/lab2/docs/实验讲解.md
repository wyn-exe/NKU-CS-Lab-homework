# 实验 2：可靠传输协议说明与代码讲解

## 实验要做什么
- 在用户态、基于 UDP 套接字实现“面向连接”的可靠传输，支持连接建立/关闭、校验和、流水线发送、选择确认、固定流控窗口、RENO 拥塞控制。
- 单向数据流（发送端→接收端），控制报文双向交互。
- 使用提供的测试文件完成传输，能在有丢包/延迟的网络中保持可靠性，并输出耗时与平均吞吐率。

## 协议设计概要
- **报文格式**（见 `src/reliable_udp.cpp` 内 `PacketHeader`）  
  `seq`/`ack`：基于字节序号；`len`：有效载荷长度；`wnd`：接收端通告的可用窗口（分片数）；`flags`：SYN/ACK/FIN/META；`sack`：32 位选择确认位图（相对 `ack` 之后的分片）；`checksum`：16 位一补和，覆盖头+载荷。
- **连接管理**  
  参考 TCP 三次握手：SYN → SYN|ACK → ACK。关闭阶段发送 FIN，接收端回复 ACK（同时带 FIN 触发最终 ACK），处理重试超时。
- **分片与流水线**  
  固定分片大小（默认 1000B），发送端维护发送窗口；接收端维护接收缓存与按序写文件，超窗口数据直接丢弃。
- **选择确认（SACK）**  
  接收端在 ACK 中填充 `sack` 位图，标记 `ack` 之后最多 32 个已收分片，发送端据此跳过已收片、降低无谓重传。
- **校验和**  
  16 位互联网校验和；解析时校验失败直接丢弃。
- **流量控制**  
  固定窗口大小由配置 `window_packets`，接收端在 ACK 中通告剩余缓存，发送端取 `min(cwnd, receiver_wnd, 固定窗口)` 作为实际可发窗口。
- **拥塞控制（Reno）**  
  `cwnd` 起始 1，`ssthresh` 初始为窗口大小；新 ACK：慢启动/拥塞避免；3 个重复 ACK 触发快重传 + 快恢复；超时回到慢启动。
- **超时重传**  
  以最早未确认分片的发送时间计算，超过 `rto_ms` 且未超过重传次数即重发并缩小拥塞窗口。

## 代码结构
- `src/reliable_udp.h`：公共接口、协议常量、配置与统计结构体。
- `src/reliable_udp.cpp`：协议核心实现（握手、分片/重传、SACK、Reno、校验和、FIN 终止）。
- `src/sender_main.cpp`：发送端 CLI 入口。
- `src/receiver_main.cpp`：接收端 CLI 入口。
- `CMakeLists.txt`：构建配置（MSVC 默认开启 `/utf-8`，自动链接 `ws2_32`）。

## 关键流程与函数
- **握手**  
  - 发送端：`Sender::handshake()` 生成 ISN，发送 SYN，等待 SYN|ACK（校验 `ack == isn+1`），再发最终 ACK，记录对端窗口。  
  - 接收端：`Receiver::handshake()` 监听 SYN，回复 SYN|ACK，等待最终 ACK，确定起始序号。
- **元数据下发**  
  `Sender::send_meta()` 发送 `FLAG_META` 报文，载荷为 `文件名|文件字节数`；接收端解析后创建输出文件，确认后开始收数。
- **数据发送与确认**  
  `Sender::send_data()`  
  - 按窗口/拥塞窗口限制发送新分片并入表 `window_`，记录发送时间。  
  - `recv_ack()` 取 ACK 后由 `handle_ack()` 更新累计 ACK、标记 SACK 片、调整 `cwnd/ssthresh`。  
  - 超时或 3 个重复 ACK 触发重传。  
  - 统计耗时、吞吐率并返回。
- **接收与按序写文件**  
  `Receiver::handle_packet()`  
  - META：解析文件名、大小，确认。  
  - 数据：校验窗口，按序写入并推进 `expect_seq_`，乱序片放入 `buffer_`；构造 `sack` 位图、通告剩余窗口并发送 ACK。  
  - FIN：回复 ACK|FIN，触发结束。  
  - 记录已收字节数，供吞吐率计算。
- **工具函数**  
  `serialize_packet()/parse_packet()` 序列化/校验；`checksum16()` 计算校验和；`make_udp_socket()` 创建并绑定 UDP；`resolve_address()` 地址解析。

## 构建与运行
1. 生成与编译（默认 VS/MSVC，可换其他生成器）：  
   ```powershell
   cmake -S . -B build
   cmake --build build
   ```
   生成的可执行文件位于 `build/Debug`（或对应配置）目录。
2. 启动接收端（示例，监听 9000，输出到当前目录 `recv_out`）：  
   ```powershell
   .\build\Debug\rudp_receiver.exe 0.0.0.0 9000 .\recv_out --wnd 32 --payload 1000
   ```
3. 启动发送端（示例，向接收端发送 `lab2测试环境/测试文件/1.jpg`）：  
   ```powershell
   .\build\Debug\rudp_sender.exe 127.0.0.1 9000 .\lab2测试环境\测试文件\1.jpg --wnd 32 --payload 1000 --rto 300
   ```
   可选 `--local-ip`/`--local-port` 固定本地地址。
4. 使用 Router 程序模拟链路（丢包/时延设置见 `lab2测试环境/router/Router程序说明.pdf`），让发送端连到 Router，再由 Router 转发到接收端，重复不同丢包率/窗口设置收集吞吐与耗时。

## 参数与调优提示
- `--wnd`：固定发送/接收窗口（分片数）；窗口过大在高丢包时重传压力增加。
- `--payload`：分片大小；过大易碎片，过小头开销增大，建议在 800~1200B 间试验。
- `--rto`：超时重传定时器（毫秒）；可以结合网络 RTT 粗略调大/调小。
- 在高丢包场景建议增大 `conn_retry` 与 `max_retransmit`（在 `Config` 中）。

# 实验 2 实验报告

## 1. 实验目的

- 在 UDP 之上实现面向连接的可靠传输，完成文件的单向可靠发送。
- 支持连接管理、校验和、流水线 + 选择重传、固定窗口流量控制、RENO 拥塞控制。
- 在给定测试文件与可模拟丢包/时延的环境中，验证可靠性并观察窗口/丢包率对性能的影响。

## 2. 实验环境

- 操作系统：Windows（VS/MSVC 17.9，C++17）；无第三方依赖。
- 代码位置：`src/reliable_udp.cpp`、`src/sender_main.cpp`、`src/receiver_main.cpp`。
- 测试文件：`lab2测试环境/测试文件`（三张图片 + 文本）。
- 丢包/延时模拟：`lab2测试环境/router/Router.exe`（参数详见同目录 PDF 说明）。
- 构建：`cmake -S . -B build && cmake --build build`，生成物在 `build/Debug`。

## 3. 协议实现概要

- 报文头：`seq`/`ack`（字节序），`len`，`wnd`（分片数），`flags`（SYN/ACK/FIN/META），`sack`（32 位位图），`checksum`（16 位一补和）。
- 握手/终止：三次握手建立，FIN + ACK 关闭；握手/关闭均有超时重试。
- 可靠传输：固定分片（默认 1000B），发送窗口受 `min(cwnd, receiver_wnd, 配置窗口)` 限制；SACK 反馈乱序块；超时与 3 重复 ACK 触发重传。
- 拥塞控制：Reno（慢启动/拥塞避免/快重传+快恢复）；流量控制使用接收端通告的剩余窗口。
- 校验与文件写入：校验和失败丢弃；接收端按序写入文件并维护乱序缓存。
- 关闭策略：接收端收到 FIN 后立即回复 FIN|ACK，并在结束后额外发送数个 ACK；发送端 FIN 阶段为最佳努力，即便未收到最终确认也结束（不影响数据完整性）。

## 4. 实验步骤

1) 构建：执行上述 CMake 命令。
2) 启动接收端（示例，监听 9000，保存到 `recv_out`）：
   ```powershell
   .\build\Debug\rudp_receiver.exe 127.0.0.1 8000 .\recv_out --wnd 32 --payload 1000
   ```
3) 可选：启动 Router，配置丢包率/时延，令发送端连接到 Router 的监听口，由 Router 转发到接收端（参数参考 PDF）。
4) 启动发送端（示例，发送 1.jpg）：
   ```powershell
   .\build\Debug\rudp_sender.exe 127.0.0.1 9000 .\lab2测试环境\测试文件\1.jpg --wnd 32 --payload 1000 --rto 300
   ```
5) 观测输出：程序结束时打印“传输字节/耗时(ms)/吞吐率(Mbps)”，并确认接收端文件校验正确（大小、哈希或直接打开图片）。

## 5. 测试设计

- **窗口敏感性**：`wnd` 分别取 8/16/32/64，记录吞吐与重传情况。
- **分片大小**：`payload` 取 800/1000/1200 比较碎片与吞吐。
- **丢包率**：Router 设置 0%、1%、5%、10% 丢包，固定时延（如 50ms），观察可靠性与吞吐变化。
- **超时参数**：`--rto` 取 200/300/500，对比超时触发频率。

## 6. 结果与分析（填写建议）

- 对比窗口变化：窗口增大后吞吐提升到一定阈值，过大时重传增多、拥塞恢复频繁。
- 丢包影响：丢包率上升时，Reno 频繁进入快速恢复/慢启动，吞吐下降；SACK 减少无谓重传。
- RTO 影响：RTO 过小导致误判超时，过大则恢复慢，需结合 RTT 微调。
- 文件大小差异：大文件能更明显体现拥塞控制曲线，小文件受握手/终止开销影响更大。
- FIN 阶段：当前实现将 FIN 确认视为最佳努力，不再阻断成功返回；若需严格关闭，可增大 FIN 重试/超时或增加握手重试。

## 7. 问题与改进

- 当前 RTO 为固定值，未做 RTT 估计，可扩展成 Jacobson/Karels RTT 平滑算法。
- SACK 仅覆盖 32 个分片，窗口更大时可扩展为可变长度或带偏移的块描述。
- 目前仅单文件单连接，可在 META 中携带队列信息支持批量发送。
- 关闭阶段未实现时间等待（TIME_WAIT）延迟，可在高丢包下追加超时保护。
- 可选改进：支持自适应窗口（接收端动态通告）、更精细的拥塞避免（如 CUBIC）、基于速率的发送节流以配合受限链路。

## 8. 总结

- 实验完成了基于 UDP 的可靠传输协议，实现了连接管理、校验和、选择重复、固定流控及 Reno 拥塞控制。
- 通过配置窗口/分片/RTO，可在不同丢包环境下达到稳定传输；进一步改进 RTT 估计与 SACK 细节可提升性能和鲁棒性。

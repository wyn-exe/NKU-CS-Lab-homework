	\section{实验要求}
	参考教材第四章零知识证明部分，完成一个证明生成与证明验证实验。实验设定为：Alice 希望证明自己知道方程
	\[
		x^{3}+x+5=out
	\]
	的解，其中 \(out\) 是公开值。本实验设定 \(out=35\)，Alice 的秘密见证为 \(x=3\)，因为
	\[
		3^{3}+3+5=27+3+5=35.
	\]
	
	实验需要实现如下内容：
	\begin{enumerate}
		\item 用代码实现证明生成过程，使 Alice 可以基于秘密见证 \(x\) 生成证明；
		\item 用代码实现证明验证过程，使验证者在不知道 \(x\) 的情况下验证证明是否正确；
		\item 在报告中说明实验原理、实验流程、关键代码、运行结果与正确性分析。
	\end{enumerate}
	
	本实验最终实现文件为 \texttt{zk\_polynomial\_proof\_lab.ipynb}。
	
	\section{实验原理}
	\subsection{零知识证明基本思想}
	零知识证明允许证明者向验证者证明某个命题为真，同时不泄露除“命题为真”之外的额外信息。对本实验而言，公开命题可以写为：
	\[
		C(x): x^{3}+x+5=35.
	\]
	Alice 要证明自己知道一个满足 \(C(x)\) 的秘密值 \(x\)，但不把 \(x\) 直接发给验证者。
	
	零知识证明通常需要满足三个性质：
	\begin{enumerate}
		\item 完备性：如果 Alice 确实知道正确见证，诚实生成的证明应通过验证；
		\item 可靠性：如果 Alice 不知道正确见证，则很难伪造一个能通过验证的证明；
		\item 零知识性：验证者只知道 Alice 知道某个满足条件的见证，而不知道见证本身。
	\end{enumerate}
	
	\subsection{Schnorr 协议与 Fiat-Shamir 变换}
	教材中介绍的 Schnorr 协议可以证明“证明者知道某个离散对数”。设椭圆曲线基点为 \(G\)，秘密值为 \(a\)，公开点为 \(PK=aG\)。证明者可以在不公开 \(a\) 的情况下证明自己知道 \(PK\) 对应的秘密值。
	
	交互式 Schnorr 协议需要验证者给出随机挑战。为了减少交互，可以使用 Fiat-Shamir 变换：将公开语句、承诺点等信息输入哈希函数，用哈希输出代替验证者的随机挑战。这样证明者只需发送一轮证明，验证者即可独立验证。
	
	\subsection{将三次方程转化为曲线点关系}
	本实验使用椭圆曲线群来表示多项式关系。设 \(G\) 是公开基点，Alice 根据秘密 \(x\) 计算：
	\[
		A=xG,\quad B=xA=x^{2}G,\quad C=xB=x^{3}G.
	\]
	若这些点确实由同一个 \(x\) 生成，则有：
	\[
		C+A+5G=(x^{3}+x+5)G=outG.
	\]
	因此验证者可以检查曲线点等式 \(C+A+5G=outG\)。
	
	但是，仅检查该等式还不够，因为验证者还需要确认 \(A,B,C\) 之间确实使用了同一个秘密 \(x\)。本实验使用两个 Chaum-Pedersen 子证明：
	\[
		\log_G(A)=\log_A(B),
	\]
	用于证明 \(A=xG\) 且 \(B=xA\)；
	\[
		\log_G(A)=\log_B(C),
	\]
	用于证明 \(A=xG\) 且 \(C=xB\)。两个证明共同约束 \(A,B,C\) 是由同一个秘密 \(x\) 逐步生成的。
	
	\subsection{实现方案说明}
	实验代码直接用 Python 实现椭圆曲线基础运算、Fiat-Shamir 哈希挑战、Chaum-Pedersen 证明生成与验证。该实现不依赖第三方密码库，便于观察每一步计算过程。
	
	\section{实验过程}
	\subsection{导入库并设置公开参数}
	首先导入哈希函数、随机数和格式化输出模块，然后设置曲线参数。该曲线满足 \(y^{2}=x^{3}+7 \pmod P\)，其中 \(G\) 是公开基点，\(N\) 是基点阶。
	
	这些参数都是公开参数，不属于 Alice 的秘密。验证者也使用同样参数完成验证。该代码片段只做初始化，因此运行后无直接输出。
	
	\subsection{实现椭圆曲线基础运算}
	教材中使用 \(aG\) 表示秘密数 \(a\) 与基点 \(G\) 的标量乘法。本实验中的 \texttt{scalar\_mul(a, G)} 就是在计算该值。下面代码实现模逆、曲线点合法性检查、点取负、点加法和标量乘法。
	
	\begin{lstlisting}[caption={椭圆曲线点运算实现}]
def mod_inv(value, modulus):
    """计算 value 在模 modulus 下的乘法逆元。"""
    return pow(value % modulus, -1, modulus)

def is_on_curve(point):
    """检查点是否在 secp256k1 曲线上。"""
    if point is INF:
        return True
    x, y = point
    return (y * y - (x * x * x + A_CURVE * x + B_CURVE)) % P == 0

def point_neg(point):
    """计算椭圆曲线点的相反数。"""
    if point is INF:
        return INF
    x, y = point
    return (x, (-y) % P)

def point_add(left, right):
    """椭圆曲线点加法。"""
    if left is INF:
        return right
    if right is INF:
        return left

    x1, y1 = left
    x2, y2 = right

    # 如果两个点互为相反数，相加得到无穷远点。
    if x1 == x2 and (y1 + y2) % P == 0:
        return INF

    if left == right:
        # 点加倍时的斜率。
        slope = (3 * x1 * x1 + A_CURVE) * mod_inv(2 * y1, P) % P
    else:
        # 普通点加法时的斜率。
        slope = (y2 - y1) * mod_inv(x2 - x1, P) % P

    x3 = (slope * slope - x1 - x2) % P
    y3 = (slope * (x1 - x3) - y1) % P
    return (x3, y3)

def scalar_mul(k, point):
    """椭圆曲线标量乘法：计算 k * point。"""
    if point is INF or k % N == 0:
        return INF
    if k < 0:
        return scalar_mul(-k, point_neg(point))

    k = k % N
    result = INF
    addend = point

    # 二进制 double-and-add 算法。
    while k:
        if k & 1:
            result = point_add(result, addend)
        addend = point_add(addend, addend)
        k >>= 1
    return result

# 基本自检：基点应在曲线上，并且 N * G 是无穷远点。
assert is_on_curve(G)
assert scalar_mul(N, G) is INF
print("椭圆曲线基础运算自检通过。")
	\end{lstlisting}
	
	运行结果：
	\begin{lstlisting}[caption={椭圆曲线基础运算自检输出}]
椭圆曲线基础运算自检通过。
	\end{lstlisting}
	
	结果分析：基点 \(G\) 位于曲线上，并且 \(N\cdot G\) 得到无穷远点，说明曲线参数与点运算实现一致。如果这里断言失败，则后续证明中的点关系验证没有意义。
	
	\subsection{实现哈希编码和 Fiat-Shamir 挑战}
	Fiat-Shamir 变换需要用哈希函数生成挑战 \(c\)。哈希输入必须包含公开语句、基点、结果点和承诺点，并且编码时需要区分整数、字符串和曲线点，避免不同数据拼接后产生歧义。
	
	\begin{lstlisting}[caption={哈希编码与 Fiat-Shamir 挑战}]
def int_to_32_bytes(value):
    """把整数编码成 32 字节，用于哈希输入。"""
    return int(value % N).to_bytes(32, "big")

def encode_point(point):
    """把椭圆曲线点编码成字节串。"""
    if point is INF:
        return b"\x00"
    x, y = point
    return b"\x04" + x.to_bytes(32, "big") + y.to_bytes(32, "big")

def encode_item(item):
    """给哈希函数准备无歧义编码，防止不同类型数据拼接后产生混淆。"""
    if item is INF or isinstance(item, tuple):
        data = b"P" + encode_point(item)
    elif isinstance(item, int):
        data = b"I" + int_to_32_bytes(item)
    elif isinstance(item, str):
        data = b"S" + item.encode("utf-8")
    else:
        raise TypeError(f"不支持的哈希输入类型：{type(item)}")
    return len(data).to_bytes(4, "big") + data

def hash_challenge(label, *items):
    """Fiat-Shamir 变换：用 SHA-256 生成不可预测挑战 c。"""
    digest = hashlib.sha256()
    digest.update(encode_item(label))
    for item in items:
        digest.update(encode_item(item))
    return int.from_bytes(digest.digest(), "big") % N

def point_to_hex(point):
    """把点转成便于查看的十六进制形式。"""
    if point is INF:
        return "INF"
    x, y = point
    return {"x": hex(x), "y": hex(y)}
	\end{lstlisting}
	
	运行结果：该片段定义辅助函数，无直接输出。
	
	结果分析：证明者和验证者会使用完全相同的公开输入调用 \texttt{hash\_challenge}，从而得到相同挑战 \(c\)。如果证明被篡改，哈希输入随之变化，验证等式将无法通过。
	
	\subsection{实现 Chaum-Pedersen 子证明}
	本实验需要证明两个离散对数相等。证明目标为存在同一个 \texttt{witness}，使得：
	\[
		\texttt{result1}=\texttt{witness}\cdot\texttt{base1},\quad
		\texttt{result2}=\texttt{witness}\cdot\texttt{base2}.
	\]
	证明者随机选择 \(r\)，计算 \(t_1=r\cdot base1,t_2=r\cdot base2\)，再计算挑战 \(c\) 和响应 \(z=r+c\cdot witness\)。
	
	\begin{lstlisting}[caption={Chaum-Pedersen 证明生成与验证}]
def prove_equal_logs(base1, result1, base2, result2, witness, label):
    """
    生成非交互式 Chaum-Pedersen 证明。
    证明目标：result1 = witness * base1 且 result2 = witness * base2。
    """
    # 1. 随机选择盲因子 r，并计算两个承诺点。
    r = secrets.randbelow(N - 1) + 1
    t1 = scalar_mul(r, base1)
    t2 = scalar_mul(r, base2)

    # 2. 用哈希生成挑战 c。
    c = hash_challenge(label, base1, result1, base2, result2, t1, t2)

    # 3. 计算响应 z = r + c * witness。
    z = (r + c * witness) % N
    return {"t1": t1, "t2": t2, "z": z}

def verify_equal_logs(base1, result1, base2, result2, proof, label):
    """验证非交互式 Chaum-Pedersen 证明。"""
    t1 = proof["t1"]
    t2 = proof["t2"]
    z = proof["z"]

    # 验证所有点都在曲线上，避免无效点攻击。
    points = [base1, result1, base2, result2, t1, t2]
    if not all(is_on_curve(point) for point in points):
        return False

    # 验证者用同样的公开输入重新计算挑战 c。
    c = hash_challenge(label, base1, result1, base2, result2, t1, t2)

    # 检查 Schnorr 型等式：z * base = t + c * result。
    check1 = scalar_mul(z, base1) == point_add(t1, scalar_mul(c, result1))
    check2 = scalar_mul(z, base2) == point_add(t2, scalar_mul(c, result2))
    return check1 and check2
	\end{lstlisting}
	
	运行结果：该片段定义证明函数，无直接输出。
	
	结果分析：若证明者知道 \(\texttt{witness}\)，则
	\[
		z\cdot base1=(r+c\cdot witness)base1=t_1+c\cdot result1.
	\]
	第二个等式同理。因此验证者可以确认两个离散对数相等，但不会直接得到 \(\texttt{witness}\)。
	
	\subsection{实现 Alice 的证明生成算法}
	Alice 先检查 \(x\) 是否满足整数方程，然后计算 \(A=xG,B=xA,C=xB\)，最后生成两个子证明。
	
	\begin{lstlisting}[caption={Alice 生成三次方程零知识证明}]
def generate_polynomial_proof(x, out):
    """
    Alice 生成证明。
    私密见证：x
    公开声明：out
    目标：证明 x^3 + x + 5 = out，但不直接公开 x。
    """
    # 实验中先在整数范围检查见证是否满足题目方程。
    if x ** 3 + x + 5 != out:
        raise ValueError("见证 x 不满足 x^3 + x + 5 = out，不能生成诚实证明。")

    # 把 x、x^2、x^3 映射到椭圆曲线点。
    A_point = scalar_mul(x, G)          # A = xG
    B_point = scalar_mul(x, A_point)    # B = xA = x^2G
    C_point = scalar_mul(x, B_point)    # C = xB = x^3G

    # 证明 A 和 B 使用同一个 x：log_G(A) = log_A(B)。
    cp1 = prove_equal_logs(
        G, A_point, A_point, B_point, x, label=f"cp1|out={out}"
    )

    # 证明 A 和 C 使用同一个 x：log_G(A) = log_B(C)。
    cp2 = prove_equal_logs(
        G, A_point, B_point, C_point, x, label=f"cp2|out={out}"
    )

    return {
        "out": out,
        "A": A_point,
        "B": B_point,
        "C": C_point,
        "cp1": cp1,
        "cp2": cp2,
    }
	\end{lstlisting}
	
	运行结果：该片段定义证明生成函数，无直接输出。
	
	代码解释：\texttt{cp1} 证明 \(B=xA=x^{2}G\)，\texttt{cp2} 证明 \(C=xB=x^{3}G\)。
	返回的证明对象包含 \texttt{out}、\texttt{A}、\texttt{B}、\texttt{C}、\texttt{cp1}、\texttt{cp2}，但不包含明文 \texttt{x}。
	
	\subsection{实现验证者的证明验证算法}
	验证者只使用证明对象完成验证，不需要 Alice 的秘密见证。
	
	\begin{lstlisting}[caption={验证者验证三次方程零知识证明}]
def verify_polynomial_proof(proof):
    """验证者验证 Alice 发来的证明。验证过程中不需要知道 x。"""
    out = proof["out"]
    A_point = proof["A"]
    B_point = proof["B"]
    C_point = proof["C"]

    # 1. 检查公开证明中的点是否合法。
    if not all(is_on_curve(point) for point in [A_point, B_point, C_point]):
        return False
    if A_point is INF or B_point is INF or C_point is INF:
        return False

    # 2. 检查两个 Chaum-Pedersen 证明，确认 A、B、C 由同一个 x 关联生成。
    cp1_ok = verify_equal_logs(
        G, A_point, A_point, B_point, proof["cp1"], label=f"cp1|out={out}"
    )

    cp2_ok = verify_equal_logs(
        G, A_point, B_point, C_point, proof["cp2"], label=f"cp2|out={out}"
    )

    # 3. 检查多项式输出：C + A + 5G 是否等于 outG。
    left = point_add(point_add(C_point, A_point), scalar_mul(5, G))
    right = scalar_mul(out, G)
    equation_ok = left == right

    return cp1_ok and cp2_ok and equation_ok
	\end{lstlisting}
	
	运行结果：该片段定义验证函数，无直接输出。
	
	结果分析：若两个子证明均通过，则验证者相信 \(A=xG,B=x^{2}G,C=x^{3}G\)。再检查 \(C+A+5G=outG\)，即可验证 \(x^{3}+x+5=out\)。本实验数值很小，远小于群阶 \(N\)，因此曲线群上的等式与普通整数方程一致。

	\section{实验结果分析}
	\subsection{正确性分析}
	正确样例中，Alice 使用 \(x=3\)，因此：
	\[
		A=3G,\quad B=3A=9G,\quad C=3B=27G.
	\]
	验证者检查：
	\[
		C+A+5G=27G+3G+5G=35G=outG.
	\]
	因此验证结果为 \texttt{True}。这体现了零知识证明的完备性。
	
	\subsection{可靠性分析}
	如果证明者不知道满足方程的 \(x\)，就需要同时伪造两个 Chaum-Pedersen 子证明，并让最终曲线点方程成立。由于挑战值 \(c\) 由 SHA-256 根据公开输入和承诺点生成，证明者不能在不知道见证的情况下自由控制挑战。篡改 \texttt{out} 或 \texttt{z} 后验证失败，说明证明与公开声明和响应值之间存在严格绑定关系。
	
	\subsection{零知识性分析}
	证明对象中包含的是曲线点 \(A,B,C\) 和子证明 \texttt{cp1,cp2}，没有直接包含 \(x\)。验证者通过离散对数关系和曲线点等式进行验证，而不是读取明文 \(x\)。
	
	需要注意的是，本实验中的 \(x=3\) 很小，方程也很简单，实际中验证者可以通过穷举猜出 \(x\)。因此本实验主要用于展示协议机制，而不是保护小范围秘密。真实场景应使用更大的秘密空间、更完整的电路约束和经过审计的密码实现。

	\section{结论与实践心得}
	本实验基于教材中零知识证明、Schnorr 协议和 Fiat-Shamir 变换的思想，实现了一个用于证明 \(x^{3}+x+5=out\) 的非交互式零知识证明程序。
	
	通过实验可以得到以下结论：
	\begin{enumerate}
		\item 当 Alice 使用正确见证 \(x=3\)、公开值 \(out=35\) 时，证明可以成功生成并通过验证；
		\item 验证者不需要知道 \(x\)，只需要验证曲线点关系和两个 Chaum-Pedersen 子证明；
		\item 篡改公开输出或证明响应都会导致验证失败，说明证明与公开声明之间存在绑定关系；
		\item 错误见证 \(x=2\) 不能生成诚实证明，说明实验逻辑能够区分正确见证和错误见证。
	\end{enumerate}
	
	本次实验加深了我对零知识证明流程的理解。教材中 Schnorr 协议的核心是“知道离散对数但不公开离散对数”，而本实验进一步将三次方程拆成多个椭圆曲线点关系，并用 Chaum-Pedersen 证明约束同一个秘密值在不同乘法步骤中的一致性。通过这种方式，可以把普通代数方程转化为可验证的密码学关系。
	
	同时，本实验也说明零知识证明工程实现需要非常谨慎。代码只是简单实现，但真实应用还需要考虑安全参数、随机数质量、输入编码、无效点检查、证明系统选择和代码审计等问题。

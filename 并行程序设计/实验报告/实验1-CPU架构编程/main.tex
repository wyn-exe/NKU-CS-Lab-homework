\section{实验一：n×n矩阵与向量内积}
\subsection{算法设计}
平凡算法按列访问矩阵元素，但C/C++中矩阵是行主存储，导致跨行跳跃访问，破坏了空间局部性。每次加载的Cache Line（如64B含8个double元素）仅用1个元素后失效，剩余7个浪费，频繁触发Cache Miss。优化算法改为按行访问，每一步外层循环为所有列累加一个行元素与向量的乘积，使得每次加载的Cache Line被完全利用，显著提升缓存命中率，充分发挥Cache容量优势。
\subsubsection{平凡算法设计思路}
核心逻辑：逐列遍历矩阵元素，每一步外层循环计算一列与向量的内积。

访存模式：矩阵按列访问（C/C++中矩阵为行主存储），导致空间局部性差，频繁触发Cache Miss。
\subsubsection{Cache优化算法设计思路}
核心逻辑：逐行遍历矩阵元素，每一步外层循环为所有列的部分内积累加一个乘法结果。

访存模式：矩阵按行访问，与行主存储匹配，充分利用空间局部性，减少Cache Miss。
\subsection{编程实现}

  void measure_time(void (*func)(), const char* name) {
  	LARGE_INTEGER head, tail, freq;
  	QueryPerformanceFrequency(&freq);
  	QueryPerformanceCounter(&head);
  	for (int i = 0; i < 100; i++) { //重复执行100次以减小误差
  		func();
  	}
  	QueryPerformanceCounter(&tail);
  	double time = (tail.QuadPart - head.QuadPart) * 1000.0 / freq.QuadPart;
  	cout << name << "总用时" <<time << " ms ;" << "平均时间: " << time / 100 << " ms" << endl;
  }
\end{lstlisting}

			col_sum[i] = 0.0;
			for (int j = 0; j < N; j++) {
				col_sum[i] += matrix[j][i] * vector[j]; //列主序访问
			}
		}
	}

\begin{lstlisting}[title=Cache优化算法：逐行访问,frame=trbl,language={C++}]
	void cache_optimized_dot() {
		for (int i = 0; i < N; i++) {
			col_sum[i] = 0.0;
		}
		for (int j = 0; j < N; j++) {
			double v = vector[j];
			for (int i = 0; i < N; i++) {
				col_sum[i] += matrix[j][i] * v; //行主序访问
			}
		}
	}
\end{lstlisting}

\subsubsection{关键观察与尝试解释}
根据实验数据与三级缓存配置（L1:2.1MB，L2:32MB，L3:36MB），结合矩阵内存占用（8N²字节），可以对实验结果做出一定分析和尝试解释。

当矩阵规模较小时（如N=64，内存占用32KB），数据完全容纳于L1 Cache（2.1MB）。此时，平凡算法（逐列访问）与优化算法（逐行访问）的时间差距较小。然而，平凡算法的跨列访问模式导致Cache Line利用率较低，引发L1 Miss率升高。尽管数据完全在L1中，这种低效的局部性仍会导致流水线停滞。优化算法通过连续的行主序访问，使Cache Line高效利用，减少Miss次数，性能差距逐步扩大。

当矩阵规模增至N=512（内存占用2MB）时，数据仍可完全保留在L1 Cache中，但平凡算法的跨列访问开始引发L1 Cache冲突，性能差距拉大至2.9倍。当N=1024（内存占用8MB）时，数据进入L2 Cache（32MB），平凡算法的访存模式彻底暴露缺陷：跨行跳跃访问导致L2 Cache Line无法有效复用，L2 Miss率飙升，每次Miss需从L3加载数据（延迟约40ns），CPI增大。而优化算法凭借行主序访问的连续性，在L2中保持接近100\%命中率，数据无需下沉至L3，CPI相对稳定，性能差距扩大至12.2倍。

当矩阵规模超过L3 Cache容量（N=4096时内存占用128MB），内存访问延迟占主导。平凡算法的性能进一步崩塌，其跨列访问导致内存访问高度随机，引发页表跳跃，有效带宽利用率较低。且此时，平凡算法的L3 Miss率较高，会增大访存开销。优化算法则通过内存访问连续性维持优势。

\subsection{结果分析}
为了印证之前的分析和解释，采集了数据规模在256，1024 和 4096 的两组实验，通过 VTune分析其各级缓存的访存次数和命中率，如表\ref{table:3}所示。

在小规模阶段（N=256，矩阵占用512KB），数据完全容纳于L1 Cache（2.1MB），但平凡算法的逐列访问导致Cache Line利用率低下，引发L1 Miss率3.7\%（命中率96.3\%），触发160万次L2访问（全部命中）。优化算法通过行主序访问使L1命中率提升至98.6\%，L2访问次数为0，此时L2的高效命中掩盖了平凡算法的局部性缺陷，两者耗时差距仅1.6倍。

在超大规模阶段（N=4096，矩阵128MB），数据远超L3容量（36MB），平凡算法L3 Miss率达18.4\%（2.9亿次Miss），触发2.9亿次内存访问，耗时显著增大；优化算法通过连续内存访问高效利用cache,利用L1和L2的高命中处理大多数据，虽然L3高Miss有部分进入内存，但量小且优化算法能通过内存访问连续性维持优势，性能差距来到9.4倍。

\section{实验二：n个数求和}
\subsection{算法设计}
对于该问题，平凡算法顺序累加（sum += a[i]）存在强数据依赖（每步依赖前一步的sum），导致流水线频繁停滞，IPC（指令/周期）被限制。多链路方法（如两路链式累加）将累加拆分为多条独立计算链（sum1 += a[i]和sum2 += a[i+1]），消除依赖后，在一个循环内同时用着多个临时变量对多个不同的位置进行累加，达到多个位置并行累加的效果，IPC提升。而递归分治通过分治策略进一步减少跨步访问，但受限于函数调用开销，性能弱于循环展开。
\subsubsection{平凡算法设计思路}
核心逻辑：顺序累加所有元素，单链式依赖。

性能瓶颈：指令级并行性差，无法充分利用超标量流水线。
\subsubsection{指令级并行算法设计思路}
两路链式累加：将累加拆分为两条独立链，减少数据依赖。

递归分治算法：两两相加后递归合并，利用分治减少依赖。

二重循环分阶段累加：非递归实现，通过循环分阶段合并中间结果。
\subsection{编程实现}
\begin{lstlisting}[title=平凡算法：链式累加,frame=trbl,language={C++}]
	double naive_sum(double* data_array, int n) {
		double sum = 0.0;
		for (int i = 0; i < n; i++) {
			sum += data_array[i];
		}
		return sum;
	}
\end{lstlisting}
\begin{lstlisting}[title=两路链式累加,frame=trbl,language={C++}]
	double unrolled_sum(double* data_array, int n) {
		double sum1 = 0.0, sum2 = 0.0;
		for (int i = 0; i < n; i += 2) {
			sum1 += data_array[i];
			sum2 += data_array[i + 1];
		}
		return sum1 + sum2;
	}
\end{lstlisting}
\begin{lstlisting}[title=递归分治算法,frame=trbl,language={C++}]
	void recursive_sum(double* a, int n) {
		if (n == 1) return;
		for (int i = 0; i < n / 2; i++) {
			a[i] += a[n - i - 1];
		}
		recursive_sum(a, n / 2);
	}
\end{lstlisting}
\begin{lstlisting}[title=二重循环分阶段累加,frame=trbl,language={C++}]
	double iterative_sum(double* a, int n) {
		int m = n;
		while (m > 1) {
			for (int i = 0; i < m / 2; i++) {
				a[i] = a[i * 2] + a[i * 2 + 1];
			}
			m /= 2;
		}
		return a[0];
	}
\end{lstlisting}

\subsection{结果分析}
从VTune数据可见，两路链式累加算法在不同规模下均显著优于平凡算法，其核心优势源于指令级并行性优化与流水线效率提升。可从以下两方面解析：

1. 指令级并行性提升：
平凡算法的单链式累加（sum += a[i]）存在强数据依赖，每条加法指令需等待前一条结果，导致流水线频繁空闲。两路链式将累加拆分为独立的两条链，消除依赖后，超标量流水线可同时执行两组加法指令，IPC提升。从指令数对比看，n=24时两路链式仅需20.1亿条指令，少于平凡算法的23.5亿条，表明其通过减少循环指令数进一步优化了指令效率。

2. 流水线停滞减少：
平凡算法的强依赖导致流水线停滞，以n=24为例，CPI=0.591意味着每指令平均消耗0.59周期，而两路链式CPI=0.365，效率提升38\%。这一差距在小规模（n=15）时本应显现，但因指令数少，时间差异不显著；当规模扩大至n=18时，两路链式CPI降至0.333，耗时进一步缩小。随着规模进一步增大（n=24），两路链式可能是通过减少分支预测失败率和缓存局部性优化，进一步巩固了优势。

\subsection{总结}
Cache优化优先级：矩阵计算中，改善访存模式（如行主序访问）的收益很高，尤其当数据规模超过缓存容量时。

指令级并行潜力：在计算密集型任务中，通过减少数据依赖（如超标量并行、循环展开）可显著提升IPC，但需减少函数调用开销。

规模敏感性：

矩阵实验：性能拐点在数据规模超过L2 Cache时（N=256）。

求和实验：递归算法在n>20时性能急剧下降，受栈深度等因素影响。

工具验证必要性：善用VTune等性能分析工具精准定位瓶颈（如Cache Miss、IPC），避免盲目优化。
\subsection{进一步优化思考}
矩阵内积：将矩阵划分为与Cache大小匹配的子块，可能进一步提升效率。

n数求和：展开为4路或8路，可能进一步减少依赖。
